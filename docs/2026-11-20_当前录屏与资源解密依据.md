## 2. `fs.zip` 已成功恢复

原包路径：`analysis/ipa/Payload/听读宝.app/fs.zip`。大小 216,366 字节；SHA-256：

`7e356b9c5575bb46f52308376d57bfc1197cc2ec799fd24c0d0847a2ccd104d0`

7-Zip 26.01 与 bkcrack 1.8.1 均确认实际文件使用传统 ZipCrypto；没有 AES extra 字段。原 ZIP 的成员如下：

| 成员 | 明文大小 | ZIP 记录压缩大小 | 压缩 / 加密 | flag | CRC32 |
|---|---:|---:|---|---|---|
| `dist/` | 0 | 0 | Store，无加密 | `0x0` | `00000000` |
| `dist/version.json` | 22 | 34 | Store + ZipCrypto | `0x9` | `17ea0671` |
| `dist/index.html` | 845 | 603 | Deflate + ZipCrypto | `0x9` | `27d8b4a1` |
| `dist/assets/` | 0 | 0 | Store，无加密 | `0x0` | `00000000` |
| `dist/assets/index-B2bGuvPN.js` | 798146 | 214863 | Deflate + ZipCrypto | `0x9` | `c23385c6` |

ZIP 中的压缩大小含 12 字节加密头，不能把其整体当作 Deflate 流。`version.json` 是 Stored 成员，因此其明文字节不需要先猜压缩参数。

恢复使用官方 [bkcrack 1.8.1 win64](https://github.com/kimci86/bkcrack/releases/tag/v1.8.1)；下载包 SHA-256 与 GitHub 发布摘要逐字核对：

`b35ba316170486e827dd41be2a771db06c75a309e660efc87217418149ca498a`

官方说明要求至少 12 字节已知明文，其中 8 字节连续。本次先对有限 JSON 排版、BOM、版本字段格式作 CRC 预检，找到一个完整 22 字节 CRC 匹配候选。候选当时仅是假设，不因文件名或 CRC 匹配就认作真实内容。两次 55 秒限时验证未完成，均停止；最后对唯一完整候选作一次 300 秒上限、最多 4 线程、Windows 低于正常优先级的验证，在 274.36 秒成功。

随后才认定恢复成功：解密到新副本，`zipfile.testzip()` 检查全部成员，7-Zip 独立复验显示 `Everything is Ok`（2 个目录、3 个文件，总明文 799,013 字节）。没有运行密码字典，没有输出恢复出的内部状态，没有使用 OAuth 秘密或请求应用后台。原 `fs.zip` 的哈希在操作后复核不变。

## 3. 解出的代码说明了什么

实际代码是已构建压缩的 React/H5 包。它不是开发时原始 TypeScript/组件项目，也不是 GCDWebUploader 上传资源。仅解析静态文本和 AST，没有执行该 JS，没有访问其中的服务。

Babel 解析 143,954 个节点，0 个语法错误，确认 17 个直接路由声明（含通配符）与 44 个直接原生调用方法名。路由涵盖：

- 教练、精听和复习：`/coach`、`/intensive-listen`、`/coach/review`、`/coach/review/plan`。
- AI 与单词：`/llm/chat`、会话详情、模型配置、技能、`/translation/word`。
- 应用功能：`/leaderboard`、`/more`、`/subscription`、`/device`。
- 账户：登录、二次验证、删除账户。

`/more` 与当前录屏的更多页具有可对照的结构。真实代码通过 `moreGetOverview` 读取 `totalSeconds`、`todaySeconds`、`abReviewCount`、`weekSeconds`、`coachReviewCount`，通过 `moreOpenEntry({entry: ...})` 交给原生层跳转：

| entry | 当前可对照的入口 |
|---|---|
| `AddFile` / `Sync` | 导入文件 / 同步音频 |
| `Playlist` / `History` | 播放列表 / 最近播放 |
| `Favorited` / `Vocabulary` / `ABNoteCard` | 我的收藏 / 单词本 / AB 笔记 |
| `Remind` / `TimeToPlay` / `Clock` / `LearningReport` | 学习提醒 / 定时播放 / 定时关闭 / 学习时长 |
| `AudioSpeedUp` / `Video2Audio` / `Podcast` | 音频加减速 / 视频转音频 / 播客 |

这些是原生桥协议与静态代码观察，不代表原生处理函数已经恢复。代码中还存在浏览器演示 fallback；不允许把示例句子、mock 标识或示例音频填成真实用户资料。

在这个已恢复包内，没有找到视频“听力”页的四六级或 EnglishPod 分类目录、文件下载映射。不能把教练中的“听力训练”文案混同为资源库。原生环境配置中的 `getApiHost()` 返回空串，部分其他分支包含站点 fallback；静态域名和认证路径不证明实际服务器配置、接口可用性或授权成功。后续必须独立核实真实资源接口或当前设备内的实际目录缓存。

脱敏索引为本地 `fs-feature-overview.json` 与 `fs-ast-overview.json`。REA 全语义分析在明确设置的每源文件 60 秒上限超时，保留的是部分观察 `ev_e680916b7a5a875c955a4929172dc74e081d19dd4dec6791e2a6b0a34723972b`；本报告没有把它写成完整调用图。

## 5. 本轮独立音频工具的验证边界

当前视频只证明更多页有音频加减速与视频转 mp3 入口，没有展示详情页面。本轮工具详情采用一致的页面风格，不作逐像素还原声明。

- `TdbAudioTools.swift` 使用 iOS AVFoundation 只读音轨，Spectral 保调时间伸缩后真实写出 AAC/M4A，或写出 16 位 PCM/WAV 供 MP3 编码。提供 0.1–5 倍速度与 96/128/192 kbps。
- MP3 使用 `shine_dart` 1.0.0 的独立 isolate 逐帧编码；没有改后缀冒充。完成后通过 iOS AVURLAsset 再验证 MPEG Layer III 与时长，失败不导入。
- 每任务独立临时目录；取消 reader/writer 后才清理；编码 worker 完成关闭文件并确认退出后才允许删除；资料库复制回调完成后才释放输出。
- 本机 13 项 Dart 测试全部通过，ffprobe 实际核验合成 PCM 的输出为 MP3、44.1 kHz、双声道、128 kbps，时长约 1 秒。没有跳过这项本机验证；这并非对 iOS 实际提取和变速路径的替代。
- 指定 Dart 文件静态检查无问题。Windows 没有 Swift/iOS SDK，因此原生编译、M4A 导出、极端速度保调效果与真机取消仍待云端及手机验收。选择 Spectral 算法不等于承诺极端速度无音质损失。
- 组件实际 LGPL 许可及重编替换说明见 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)，未替整个应用指定新许可。
