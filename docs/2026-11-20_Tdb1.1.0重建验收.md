# Tdb 1.1.0 重建与验收

本轮按当前用户录屏重建五栏与独立播放器，修复 Wi-Fi 的地址选择与上传流程。原版完整源码没有恢复，在线听力服务和未演示流程也不作完成声明。

## 依据

- 当前录屏及原资源包的证据与哈希：[当前录屏与资源解密依据](2026-11-20_当前录屏与资源解密依据.md)。录屏和帧图仅保留本地忽略目录，没有推送到公开仓库。
- 文件根目录、播放器、更多与我的按当前录屏核对；录音详情、转换详情等未展示部分使用独立实现。
- `fs.zip` 解密成功不代表 FairPlay 主程序解密成功。主程序仍有 `cryptid=1`，没有恢复原在线听力服务器接口。

| 检查 | 结果 | 边界 |

| 完整 Flutter 静态检查 | No issues found | 不替代 Swift 编译 |
| 合并回归测试 | 174 通过、1 跳过 | 跳过项为 Windows 无目录符号链接创建权限；随后补充的活动文件检查另有定向测试 |
| 主界面流程 | 五栏、直属文件夹、播放器推入/返回、批量移动/删除与导入页通过 | 使用受控音频及存储替身；不是 iPhone 实际录音验证 |
| 资料库与仓库 | 联合 25 通过、1 跳过 | 覆盖保存队列、失败回滚、并发字幕关联、录音引用及活动文件保护 |

## 后续原生回归与已复现修复

- [GitHub run 9](https://github.com/hysgit/tdb/actions/runs/44682441898) 的 `ios` 与 `ios-runtime` 任务成功。后者使用 App 公布的非回环 LAN 根地址，主机真实上传 Introduction.mp3，程序逐字节核对落盘副本、实际调用常亮通道和原生波形解码；不能替代独立电脑与物理 iPhone 的网络验收。
- 同轮 `ios-audio` 已进入真实 Dart 测试，M4A 在 1.5 倍速下导出并通过系统加载及非零波形验证，日志报告 `duration_us=600000`、`decoded_samples=48`。
- MP3 的中间 WAV 写入阶段触发 `NSInvalidArgumentException`：`AVAssetWriterInput` 缺少必填 `AVLinearPCMIsNonInterleaved`。这是原生功能错误，不能因 Dart/编译测试通过而忽略。
- 提交 `9c39b07` 将该参数补入读写共用 PCM 设置字典，保持串行任务和临时文件管理不变；源码构建号更新为 4。既有真实 iOS 音频测试作为失败复现和修复验收，不添加只比对代码文本的替代测试。
- 修复后需要重新通过真实 MP3 导出/原生解码，再发布 TestFlight 构建 4。先前构建 3 的 Testing 与安装状态仅代表分发完成，不代表 MP3 功能通过。
- GitHub run 7 曾分别遇到只读模拟器枚举超时和启动日志端口发现等待；run 8 的两份探针在 Xcode 编译期间被过紧的 180 秒静默限时结束。后续探针修正了编译/运行阶段，并保留整体限时与最多一次的测试启动恢复；没有改动 Flutter SDK、安全配置或生产功能来掩盖失败。
