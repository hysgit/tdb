# Tdb 1.1.0 重建与验收

本轮按当前用户录屏重建五栏与独立播放器，修复 Wi-Fi 的地址选择与上传流程。原版完整源码没有恢复，在线听力服务和未演示流程也不作完成声明。

## 依据

- 当前录屏及原资源包的证据与哈希：[当前录屏与资源解密依据](2026-11-20_当前录屏与资源解密依据.md)。录屏和帧图仅保留本地忽略目录，没有推送到公开仓库。
- 文件根目录、播放器、更多与我的按当前录屏核对；录音详情、转换详情等未展示部分使用独立实现。
- `fs.zip` 解密成功不代表 FairPlay 主程序解密成功。主程序仍有 `cryptid=1`，没有恢复原在线听力服务器接口。

## 后续原生回归与已复现修复

- [GitHub run 9](https://github.com/hysgit/tdb/actions/runs/44682441898) 的 `ios` 与 `ios-runtime` 任务成功。后者使用 App 公布的非回环 LAN 根地址，主机真实上传 Introduction.mp3，程序逐字节核对落盘副本、实际调用常亮通道和原生波形解码；不能替代独立电脑与物理 iPhone 的网络验收。
- 同轮 `ios-audio` 已进入真实 Dart 测试，M4A 在 1.5 倍速下导出并通过系统加载及非零波形验证，日志报告 `duration_us=600000`、`decoded_samples=48`。
- MP3 的中间 WAV 写入阶段触发 `NSInvalidArgumentException`：`AVAssetWriterInput` 缺少必填 `AVLinearPCMIsNonInterleaved`。这是原生功能错误，不能因 Dart/编译测试通过而忽略。
- 提交 `9c39b07` 将该参数补入读写共用 PCM 设置字典，保持串行任务和临时文件管理不变；源码构建号更新为 4。既有真实 iOS 音频测试作为失败复现和修复验收，不添加只比对代码文本的替代测试。
- 修复后需要重新通过真实 MP3 导出/原生解码，再发布 TestFlight 构建 4。先前构建 3 的 Testing 与安装状态仅代表分发完成，不代表 MP3 功能通过。
- GitHub run 7 曾分别遇到只读模拟器枚举超时和启动日志端口发现等待；run 8 的两份探针在 Xcode 编译期间被过紧的 180 秒静默限时结束。后续探针修正了编译/运行阶段，并保留整体限时与最多一次的测试启动恢复；没有改动 Flutter SDK、安全配置或生产功能来掩盖失败。

- 补充环境 [Codemagic Native Checks 2](https://codemagic.io/app/6afef749aec4811f2d5c1021/build/6affe2478f52ca2751292f81) 在 iOS 26.5 / iPhone Air 模拟器中失败：首个音频导出流程未完成，随后测试结束时等待 `service.cancel()` 30 秒再次超时，堆栈指向 `integration_test/audio_tools_test.dart:181`。没有格式通过标记，后续 LAN 步骤没有执行。具体子阶段与原因仍未知，不能把该平台记为通过，也不能把它与 GitHub 的成功结果合并成全平台结论。
- 用户明确反馈真实手机的 Tdb 上传页仍打不开。当前电脑与手机在同一 IPv4 子网，路由为本地 WLAN 直达；指定手机 IP 的两次 ICMP 均成功，但直接 TCP80 在 5 秒内未连通，绕开代理的 HTTP 请求也超时。系统代理当时关闭。详细地址、邻居信息与时间仅存本地忽略目录 `dist/phone-wifi-diagnosis/`，没有推送公开仓库。
- HTTP 令牌、CORS、字幕导入都发生在 TCP 建连后，不能解释这次 TCP connect 超时。现有服务支持根路径 GET，显示的端口来自实际绑定结果；但监听流的错误目前被静默处理，地址显示本身不证明后续服务始终活跃。
- Apple [TN3179 的 Local network operations 表](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy#Local-network-operations)明确：`Listening for and accepting incoming TCP connections` 不要求 Local Network Privacy 授权；主动出站 TCP 则要求。不能据此先让用户盲目改权限或添加 Bonjour。文档同时说明模拟器不支持 Local Network Privacy，模拟器不替代真实设备。
- 下一步已请用户先退出 Tdb 传输页，再打开原版的 Wi-Fi 批量上传页并保持前台，提供该页地址作同手机对照。若原版可达，继续缩小到两 App 的服务监听、生命周期等差异；若原版也不可达，继续核查端口方向的网络阻断。两种结果都不能仅凭 ping 成功指定根因。
- 线上听力、同步、播客与原版完整精听等仍未恢复，原版 AI 入口仅确认存在，接口尚未连接。Wi-Fi 实机问题和补充平台音频超时均保持未完成状态。
